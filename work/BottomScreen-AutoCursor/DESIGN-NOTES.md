# Design and implementation notes

Version 0.2.11 fixes initial DPI autoscaling: suspend MainForm layout before setting Font and the 96-DPI baseline, construct all children, then resume once. Early empty-form layout previously consumed the initial scale, leaving pixel bounds and fonts inconsistent after switching to 1080p. Convert physical work-area height to logical units before selecting the initial client height. Keep PerMonitorV2 and the existing appearance. Native self-tests send WM_DPICHANGED only to the owned settings HWND through 144, 96, 192, 96 and the original DPI; assert button text/padding, single-line labels, logical width and row centering, and save screenshots. The full 314 checks include existing capture startup and GPU regressions. These synthetic DPI messages do not change the user's display mode; actual hardware mode switching remains user validation. No capture/render/input/HDR code changed.

Version 0.2.10 fixes an actual Start-button regression: optional source Auto HDR readiness was used as a capture gate. HDR is now completely decoupled from Start: only the explicit Apply button queries/writes the source preference and checks restart state. The checkbox saves intent only. Start preserves informational restart/error warnings but never processes HDR. Restart markers remain truthful and the utility never restarts a game. Real source-window and output-display validation still gate capture. Full UI integration tests click Apply to establish pending-restart, failed-query and matching-HDR states, then click Start, assert no further HDR queries, check the initial visible overlay, wait for actual source frames, verify monitor bounds, and click Stop; 208 checks pass. Foreground monitoring may normally hide the overlay when the owned source loses focus. These tests use owned fixture windows and fake executable preference paths, never third-party game input or game registry mutations. This fix adds no per-frame work.

Version 0.2.9 changes the HUD to source-image update FPS. A GPU image version is counted once only after successful Present; pointer movement, pointer removal, HUD refresh, repeated cached draws, and copies not yet submitted do not increment the counter. No full-frame comparison, readback, flush or extra synchronization is introduced. The approximately one-second elapsed-time meter may report zero for static scenes and is not clamped to monitor Hz. This is a count of distinct-source submissions, not proof of panel scanout; composition may discard submitted frames. The settings telemetry uses the same picture counter. Diagnostics retain their separately defined capture-driven submittedFps field. Native self-test passes 186 checks, including the new counting cases. GitHub Actions builds and verifies the two release directories and a clean portable ZIP on every push.

Native Windows utility, not a browser application. The design-taste-frontend app-screen direction was Framed sheet, seed 1931313653. No redraw. Tinted frame, flat white settings area, neutral controls and a single teal data region; no dashboard metrics or decorative icons.

Version 0.2.8 preserves the existing style and simple BottomScreen title. Actual native control bounds are centered after the TableLayoutPanel layout engine, including high-DPI ComboBox height changes. Auto HDR targets the captured window owner's executable, resolved with limited process query access and checked against PID reuse. Historically Apply or capture start wrote that path's Auto HDR token; version 0.2.10 restricts this to explicit Apply only. Toggling the checkbox, browsing windows, starting capture or starting the utility does not mutate graphics preferences. Use the locally observed AutoHDREnable=48 value; preserve GPU preference, windowed optimization, unknown tokens, all other application entries and global settings. Allow removes the selected game's override to inherit global policy. Changed preferences require manual game restart, with a persisted marker compared against process creation time. Never restart or kill a game automatically. Preserve legacy BottomScreen preferences. Registry schema remains undocumented, observed on build 26300, and checked by readback. Capture/output remain SDR BGRA8.

Version 0.2.8 latency review: set and read back IDXGIDevice1 maximum frame latency to 1, retain the two-buffer flip composition swap chain and Present(0,None). Choose the newest of at most two immediately available WGC frames without spinning. Enqueue the source GPU copy and release the capture frame before drawing/Present, consistent with Microsoft's HWND capture sample. Cache source texture metadata; reuse the GPU image for exact duplicate source identity and static cursor redraws. Skip redundant submissions unless cursor or periodic HUD refresh changed. Publish immutable cursor status so UI heartbeat does not wait behind rendering. Production has no full-image CPU readback, per-frame Flush, mouse remapping, input hooks, or per-frame disk logging. Queue limits and CPU timings are not input-to-photon measurements. Full native self-test passes 179 checks, including cached-scene pixels after source disposal, four native cursor styles, frame release order, queue readback, and fake-path HDR preference integration. Real game/HDR/320Hz behavior remains for user testing.

The screen answers: which physical screen area will my game fill? Its distinctive element is the bottom-aligned physical size preview, calculated from the same geometry as the actual output. Real window and display information populate selectors. No invented performance figures.

Platform adaptations: native WinForms controls and Microsoft YaHei UI provide Chinese text, keyboard focus and high-DPI support; IBM Plex Sans does not cover the Chinese interface. Browser layout checks are not applicable to a native HWND application; settings and actual composed output are captured by the application's self-test and visually reviewed. This is a resizable desktop utility, with scrolling on smaller screens, not a phone web app.

One renderer is shared by both desktop modes. The game is captured at its own window resolution, cropped to its client area, sampled by a GPU pixel shader to a 16:9 viewport, and composited into a native output buffer at the real monitor's current signal dimensions. No virtual display driver, game-process injection, desktop mode change, or game window mutation.

Version 0.2: remove the previous fullscreen-sized-client rejection. Add an explicit source selector with full client content as the safe default and optional centered 4:3 selection for pillarboxed sources. Never infer black bars or crop ordinary 16:9 content by default. Report original client and sampled source dimensions separately. Extend self-tests to cover a genuine native-resolution borderless fullscreen source and a synthetic pillarboxed 4:3 frame.

Version 0.2.1: measured submission FPS inside the existing top black region, enabled by default. Count successful Present calls over actual Stopwatch time; refresh the small text texture roughly once a second. Draw it as one extra GPU quad before the existing Present, not as an additional window, extra presentation loop, or full-frame CPU readback. Display source terminology precisely: this is submission throughput, not game FPS, scanout proof, or measured latency. Add deterministic counter tests and GPU-pixel checks for text visibility and no overlap with the game region.

Version 0.2.4: normal startup disables per-stage profiling, performance queue and disk writer; --diagnostics explicitly enables them. Normal UI contains neither diagnostic action button. Preserve the zero WGC minimum interval and original submission HUD. Do not introduce a menu hotkey or mouse remapping; the user declined a temporary original-view workaround. Latest real CS2 log: 66670 submissions in 206.7308 seconds, including 34060 repeated source timestamps; approximately 157.74 timestamp-distinct updates per second on 160Hz, not proof of panel scanout.

Version 0.2.6: directly based on 0.2.4, automatic original-shape cursor with no mouse/keyboard hooks and no input routing. Native WGC cursor capture disappears when MagShowSystemCursor hides the desktop pointer, confirmed locally, so keep native WGC cursor disabled and independently copy GetCursorInfo shape/hotspot with CopyImage/GetIconInfo/DrawIconEx. Rasterize onto black and white backgrounds once per shape change; a GPU shader reconstructs color/alpha/XOR against the original GPU image. Dynamic animation frames are not synchronized. Pointer movement over static scenes redraws only from the cached GPU image. A separate helper owns transient MagShowSystemCursor hiding while the selected source is foreground, pointer lies inside the actual sampled source rectangle, copied cursor rendered successfully, and a 750ms lease is fresh. Restore on focus loss, pointer exiting crop, stop, main UI hang or process death; primary attempts recovery if helper fails. No SetSystemCursor, ShowCursor counter changes, game memory access or injection. Self-tests use owned fixture windows and child processes, never game input.
