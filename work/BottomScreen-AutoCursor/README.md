# BottomScreen 0.2.9

适用于 Windows 11 x64。支持普通窗口和全屏窗口化（无边框全屏窗口），将游戏窗口画面拉伸到16:9区域，提供24寸/27寸预设，水平居中、底部对齐，上方及左右填黑。

本版继续基于0.2.4，保留底部居中、24/27寸、原有捕获性能修正，顶部改为画面更新帧率，日志和两个诊断按钮默认关闭。开始显示后自动绘制小屏光标，并临时隐藏原位置的系统光标；不需要鼠标5切换，也没有坐标纠正或鼠标消息转发。

## 0.2.9 更新

- 顶部改为“画面更新 FPS”：每张新源画面成功提交后仅计数一次，排除重复源帧、光标移动、光标隐藏和统计文字刷新产生的缓存重绘。仅复制但未成功提交的画面不计数。
- 约每秒按实际经过时间更新，不用显示器 Hz 或游戏 FPS 填充；源画面不更新时可以降为 0 FPS。不同源帧按捕获时间戳及尺寸/裁切身份区分，不做整帧像素比较或 CPU 读回。
- 这是程序可测的不同源帧更新率，不能精确代表面板最终显示的帧数；系统合成仍可能丢弃已提交帧。顶部保留这一口径说明，避免把它叫作“面板实显 FPS”。
- 186 项自身窗口与 GPU 自检通过。项目纳入 Git，并新增每次推送自动构建 Windows x64 ZIP 的 GitHub Actions。

## 0.2.8 更新

- 窗口标题仅显示 BottomScreen，版本号保留在文件属性中。
- 标签、下拉框、尺寸输入与刷新按钮按实际控件高度垂直居中，修复高 DPI 下下拉框与左右控件错位。
- 自动 HDR 改为作用于被捕获的游戏：选择正确的游戏窗口，保持“允许所选游戏使用自动 HDR”不勾选，点击“应用设置”。首次写入或更改配置后，按提示手动重启游戏，再刷新窗口列表并开始显示；不需要重启 BottomScreen。
- 勾选表示移除所选游戏的自动 HDR 覆盖，跟随 Windows 全局设置，不强制开启 HDR。切换复选框、浏览窗口列表本身不会修改其他程序的 Windows 图形配置；“开始显示”也会核对并应用当前选择。
- 捕获帧在 GPU 复制指令提交后立即释放，避免占用捕获缓冲区等待显示提交。已有较新帧时优先处理较新的一帧；设置并读回 DXGI 最大排队帧数为 1。
- 相同源时间戳、尺寸和裁切区域复用已有 GPU 画面；画面与光标均不变时跳过重复提交。静止菜单中移动光标只重画缓存画面。光标守护心跳不再等待渲染锁。
- 179 项自身窗口与 GPU 自检通过。实际游戏的 320Hz 吞吐、自动 HDR 效果和端到端延迟仍需实测，不能承诺完全等于原生游玩。详见同目录《性能与延迟复核.md》。

## 自动 HDR 的范围

只修改所选窗口所属游戏 EXE 路径的 Windows 自动 HDR 首选项，保留该路径的 GPU 选择、窗口化游戏优化及未知配置。不修改全局自动 HDR、Windows HDR 总开关或游戏内部配置。设置按完整 EXE 路径区分，不按游戏标题区分；请选择游戏本体窗口，避免选到启动器。游戏移动到新路径后需要重新应用。

更改应用到已经运行的游戏时，需要手动重启游戏；程序会提示并暂缓开始捕获。重启提示会保存，关闭再打开 BottomScreen 不能代替重启游戏。仅启动 BottomScreen 不会改动任何程序的 HDR 配置，也不会自动重启游戏。旧版本为 BottomScreen 自身写入的图形首选项保留，不擅自清理用户已有设置。

本机 Windows build 26300 的系统设置已实测：关闭单应用自动 HDR 会保存 `AutoHDREnable=48;`。程序沿用此配置并核对写入后的值。此注册表格式不是公开稳定的 DXGI API；未来 Windows 更改规则时可能需要适配。写入失败会在界面提示，不会把失败显示为已生效。

这不是原生 HDR 输出开关。现有捕获与输出仍为 SDR 8-bit，没有增加 HDR 捕获/输出或 HDR 转 SDR 色调映射。禁用游戏的自动 HDR 不会关闭游戏自身的原生 HDR。允许仅表示交由 Windows 判断，最终是否触发及游戏中的色彩效果需实测。

Windows 图形设置中的同名项按完整 EXE 路径区分。移除某个旧版条目只会删除该路径的首选项，不会卸载程序；本版不会自动清理其他版本的条目。

## 自动单光标

- 退出旧版，启动本版，照常选择游戏与尺寸，然后“开始显示”。鼠标5恢复为游戏原有功能，没有新增切换快捷键。Ctrl+Alt+F10仍用于停止并返回设置。
- 软件读取当前真实系统光标，复制它的图像、尺寸和点击热点，在GPU中按游戏画面相同的裁切、缩放位置绘制。支持普通箭头、手形、文本光标、单色反色光标等；样式句柄变化时会更新。动画光标目前使用复制时的静态帧，不承诺同步每一帧动画。
- 小屏光标成功显示后，使用Windows临时显示接口隐藏原位置的系统光标。不修改鼠标主题，不替换全局光标资源，不改鼠标坐标、不转发输入、不注入游戏。点击仍发生在原来的真实位置，你看小屏光标定位。
- 光标移出所捕获的源区域（或移出所选4:3裁切区域）、切出游戏、停止、关闭窗口时恢复系统原光标。游戏本身隐藏光标时不强制画一个；游戏自行绘制的软件光标已经包含在原画面中。
- 独立恢复进程检查前台窗口和短期心跳；主程序卡住约0.75秒或意外退出时，会释放本程序的隐藏状态。程序目录也附有“恢复系统光标.cmd”，可用于手动恢复。恢复进程异常时主程序也会停止并尝试恢复。如果无法复制当前光标，保留原光标，避免无指针可用。

采用GPU小图层合成；光标图像仅在样式变化时重新复制。静止菜单中的光标移动可复用已有GPU画面，不需要整帧CPU读回或重新捕获。窗口捕获和游戏渲染设置仍沿用原逻辑，未增加全局鼠标/键盘监听。

自身窗口测试覆盖原光标复制、隐藏后小屏仍可见、心跳超时恢复、父进程异常结束恢复，以及原有捕获和GPU输出检查。没有操作CS2，实际游戏和平台体验仍由用户验证。对于隐藏系统光标、使用游戏自绘或原始输入的菜单，不推测游戏内部光标状态。320Hz吞吐、HDR和端到端延迟仍需实测。

## 本次实战结果

0.2.3在这台4K 160Hz、RX 9070电脑上的CS2测试持续206.73秒，成功提交66670次，整体平均322.50次/秒；其中34060次与上一帧源时间戳相同。按源时间戳区分的新更新约157.74次/秒，接近160Hz，不代表显示器实显322个不同画面。稳定区间大多每秒提交约330次，仍出现少数短暂低帧区间；原先持续约57FPS的现象已消失。没有空取帧、缓冲重建或日志丢样本。

## 锐利像素和菜单

“锐利像素”勾选后使用最近邻采样，每个输出像素直接取邻近的源像素；边缘可能显得硬，但锯齿、闪烁和细线粗细不均也可能更明显。关闭时使用双线性采样，画面更平滑，可能略软。这不是额外的锐化滤镜，不增加分辨率，不改变物理尺寸，不还原已经丢失的细节；只作用于本程序的缩放阶段。游戏在此之前已经做过的拉伸或模糊，无法靠这个选项撤销。

菜单错位的原因是画面缩放、下移，但鼠标点击仍使用原游戏窗口坐标。真正做到小屏内准确操作，需要按裁切与缩放关系映射菜单坐标，并验证不影响对局中的相对鼠标输入。当前版本未实现这种菜单映射；按用户要求，不加入临时切回原画面的菜单快捷键。

## 0.2.3修正内容

旧版CS2实战日志显示：在4K 160Hz、RX 9070下，稳定时通常约57FPS；每个回调处理平均0.375毫秒，Present平均0.261毫秒，而捕获源时间戳平均间隔17.840毫秒。主要表现为上游交付节奏偏慢，并非CPU每帧绘制花了约18毫秒。

随后在同一电脑上读取新建WGC会话的`MinUpdateInterval`，实测默认值为16毫秒。旧版没有设置它，这是一个与现象吻合的限制。新版在系统支持时显式设置为`TimeSpan.Zero`，并读回确认；`0`表示不施加该最小间隔，不代表无限帧率或保证160/320FPS。

采用较新Windows SDK进行编译，最低系统支持仍保留19041；没有该属性的系统跳过设置并如实记录。日志会增加`minUpdateIntervalSupported`、`originalMinUpdateIntervalMs`、`requestedMinUpdateIntervalMs`和`appliedMinUpdateIntervalMs`，可区分系统原值、请求值和读回值。此版只针对这个变量修正，保留原缓冲数量、GPU路径和提交方式，便于前后对照。

上述修正在0.2.3实战中已验证改善。0.2.4沿用相同的捕获、缩放和提交参数，仅在正常启动时关闭诊断采样与日志写入，隐藏诊断控件。

## 可选性能诊断（默认关闭）

正常双击启动不会创建性能日志文件或性能记录后台任务，逐段耗时采样也关闭。只有异常时仍可能生成`BottomScreen.log`错误日志。已有的旧版日志不会被删除。顶部画面更新帧率统计不依赖性能日志，仍可使用。

若以后需要排查问题，先退出已运行实例，再显式以`BottomScreen.exe --diagnostics`启动，才会打开性能采样并显示两个诊断按钮。以下说明仅适用于这种手动诊断模式：

1. 退出旧版本，运行本版；保持当前4K 160Hz和原游戏设置开始测试。
2. 在同一对局连续运行30–60秒，期间尽量保持游戏前台，不切屏、不切换显示模式。
3. 按Ctrl+Alt+F10停止，然后点击“打开性能日志”。把最新的`performance-日期-时间-编号.jsonl`提供用于分析；不必手动解读。

诊断模式下每次开始会生成一个日志，路径在程序旁的`logs`目录，约每秒汇总一次。记录输出分辨率、Hz、实际捕获纹理尺寸、裁切区域、显卡型号，以及以下各段的平均值、95百分位和最大值：

- `callbackGapMs`：程序收到捕获回调的时间间隔；回调内的阻塞也可能影响这个间隔，不能单独把它解释成捕获API的独立速度上限。
- `sourceTimestampGapMs`：WGC提供的源帧时间戳差值；只计算相邻帧间隔，不据此推算端到端延迟。
- `lockWaitMs`、`acquireMs`、`prepareMs`：回调锁等待、取帧、纹理访问及裁切准备耗时。
- `resourceSetupMs`、`copyEnqueueMs`、`drawEnqueueMs`、`hudMs`：纹理准备、复制指令提交、绘制指令提交和帧率文字处理耗时。
- `presentMs`：Present调用在CPU上的实际耗时，包括调用内发生的等待。
- `callbackTotalMs`：从回调入口到即将退出的处理总耗时，包含锁等待，不包含后台日志写盘。
- `submittedFps`、`empty`、`recreates`、`sourceRepeated`、`droppedLogSamples`：成功提交率、空取帧次数、缓冲重建次数、源时间戳重复次数和日志队列溢出丢失样本数。日志丢样本时统计不完整，需要一并考虑。

所有阶段计时都是CPU侧耗时，**不是GPU真实执行时间**。复制与绘制指令异步执行，CPU提交很快不能证明GPU没有瓶颈。0.2.8 在 GPU 复制指令提交后、绘制和 Present 前释放捕获帧，并限制 DXGI 排队帧数为 1。诊断新增较旧帧替换、重复源画面复用、跳过重复提交和提前释放计数。“游戏300+、本程序50+”仍不能单独区分捕获交付、GPU 争用和下游处理的影响。

后台任务负责聚合和写盘，捕获线程只向有容量上限的队列投递数值样本，不逐帧写文件。正常停止会排空日志并写入总帧数和停止原因。若程序崩溃或被强制结束，最后一段可能未保存。本版日志未加入无帧期间的定时心跳，长时间无回调通过下次回调间隔或停止汇总体现。写入失败会记录到`BottomScreen.log`，正常停止时也会在界面提示。日志不记录游戏截图、窗口标题或按键。

诊断保留原值、请求值和读回值，方便后续对照；不把源更新、提交次数或显示器Hz混为一谈。

## 顶部黑边帧率

默认开启“顶部黑边显示画面更新帧率”。画面上方居中显示例如“画面更新 149.5 FPS | 刷新 160 Hz”。刚启动时会短暂显示“采样中”。

- FPS 按成功提交的新源帧数除以实际经过时间计算，约每秒更新；同一张缓存画面只计一次，光标和文字重绘不计入。不是拿显示器 Hz 或游戏 FPS 填入，也没有进行高成本的整帧像素比较。
- 它用于观察本程序捕获、缩放并提交不同源帧的更新速率。它不是 CS2 自身 FPS，也不是经过显示器扫描反馈测量的实显帧率。系统合成可能丢弃已提交帧，不能据此证明面板显示了同样数量的不同画面，数值也不会人为钳制到显示器刷新率。
- Hz读取启动时选定显示器的当前刷新率。例如你当前4K 160Hz模式就显示160Hz。
- 文字绘制进原有GPU输出的顶部黑边，不遮挡24/27寸游戏区域，不增加独立悬浮窗口。文字小贴图约每秒更新一次；没有每帧读取整屏到CPU。若要对比开销，可以停止后取消勾选。
- 旧版若重复提交约 320 次、实际源更新约 160 次，新版接近 160 FPS 不表示画面更新变慢。0.2.9 进一步排除光标和文字的缓存提交；静止菜单即使光标在移动，也不会因此抬高画面更新 FPS。

## 第一次使用

1. 先退出正在运行的旧版本，再运行固定目录 `outputs\BottomScreen\BottomScreen.exe`。不需要安装，不需要管理员权限，不需要开启AMD驱动的GPU缩放。每版同时保留 `BottomScreen-v版本号` 归档，固定目录更新以延续快捷方式和 Windows 图形首选项。
2. 在Windows/显示器中先选择想用的模式，例如3840×2160，或者1920×1080、320Hz。本程序不会修改分辨率或刷新率。
3. 打开CS2，使用**窗口模式或全屏窗口化**。本程序不负责强制设置游戏渲染分辨率。若要真正按1280×960渲染，需游戏本身在当前模式支持相应设置；不能通过裁切画面代替渲染分辨率设置。独占全屏没有验证，不属于本版支持范围。
4. 在本程序点击“刷新”，选择CS2窗口、正确的输出显示器。实体屏幕尺寸保留31.5寸，模拟尺寸选24寸或27寸。新增“画面来源”：游戏已铺满或普通4:3窗口选**完整画面**；只有画面左右存在黑边、游戏内容为居中4:3时，才选**居中4:3去黑边**。
5. 自动 HDR 默认关闭：点击“应用设置”，如果提示重启游戏，请手动重启游戏、刷新并重选窗口。配置匹配后，建议先进入练习对局，再点“开始显示”。程序会最小化，游戏获得焦点，完整画面被拉伸铺满所选区域。
6. 按 **Ctrl + Alt + F10** 停止，立即返回设置窗口。如果此快捷键被占用，程序会禁止开始并提示原因。

切换4K/1080p或刷新率时，程序会安全停止并刷新显示器信息；确认新模式后再次点击“开始显示”。不需要更换程序。游戏窗口自身分辨率改变时会重新建立捕获缓冲区。

## 全屏窗口化怎么选

- 全屏窗口化中的游戏画面已经拉伸铺满整屏：选“完整画面”，保留全部内容，再缩放到所选物理区域。
- 全屏窗口化中，4:3游戏画面居中、左右有黑边：选“居中4:3去黑边”，截取客户区中央4:3区域，再横向拉伸铺满模拟区域。这是按比例选择区域，不是自动识别黑边。
- 正常16:9画面没有左右黑边：选“完整画面”。误选去黑边会裁掉左右游戏内容。
- 例如全屏窗口为3840×2160时，去黑边选择的中央区域为2880×2160；这不表示游戏内部变成1280×960。程序会同时显示窗口尺寸与实际采样区域尺寸。

## 先检查效果

如有需要，可显式用`--demo`打开独立测试画面，或者在`--diagnostics`模式点“打开测试画面”。正常界面不显示这个按钮。再刷新窗口列表，选择“BottomScreen 测试画面”，可像游戏一样捕获。红、绿、蓝、白四个象限应完整显示；圆形会因4:3拉伸到16:9变成横向椭圆。这可直观看出拉伸是否正确。

## 分辨率与物理尺寸

本程序不安装虚拟显示驱动，也不向系统新增一个独立显示器。它使用当前真实显示器的输出分辨率创建显示画面，游戏源画面分辨率由游戏自行设置。

例如桌面4K时程序按3840×2160输出；桌面1080p时按1920×1080输出。24寸/27寸区域占用整屏的一部分像素，并非在同一块屏幕里另造一块完整4K面板。

按31.5寸、16:9面板计算（像素取整）：

| 当前桌面输出 | 模拟尺寸 | 区域像素 | 区域左上角，相对该显示器 |
|---|---:|---:|---:|
| 3840×2160 | 24寸 | 2926×1646 | 457, 514 |
| 3840×2160 | 27寸 | 3291×1851 | 274, 309 |
| 1920×1080 | 24寸 | 1463×823 | 228, 257 |
| 1920×1080 | 27寸 | 1646×926 | 137, 154 |

## 操作与已知限制

- **键鼠：**输出窗口不获取焦点，鼠标穿透给原游戏。本程序不注入游戏、不模拟瞄准输入。游戏内相对鼠标输入仍交给原游戏。不做鼠标坐标重映射；菜单操作时看小屏内复制的光标定位，实际鼠标坐标和点击逻辑保持不变。
- **切出游戏：**Alt+Tab切到其他窗口时隐藏小屏输出；回到原游戏窗口时恢复。游戏关闭或最小化时停止。
- **显示器切模式：**自动安全停止，再次开始时使用新的输出尺寸；没有修改显示器模式的权限需求。
- **锐利像素：**选中时使用最近邻采样，细节更硬，可能有明显锯齿；关闭时使用双线性平滑。两者都不能恢复缩小时丢失的细节。
- **性能：**使用Windows Graphics Capture + Direct3D11 + DirectComposition，图像在显卡内复制和缩放。顶部和设置窗口显示成功提交的不同源帧更新率，不是游戏 FPS 或延迟。诊断日志的 submittedFps 仍记录捕获回调驱动的成功提交率，不与顶部指标混用。Windows合成器、驱动、游戏及捕获机制都可能影响更新频率。显示器320Hz不代表捕获一定达到320帧，排队上限为1也不等于端到端只增加1帧延迟。
- **HDR：**首版使用8位SDR捕获与显示路径。建议先在SDR下使用；HDR颜色、亮度和色调映射没有验证。
- **捕获限制：**游戏权限更高、窗口受保护、反作弊限制或系统禁用捕获时，可能无法正常捕获。不同反作弊平台的兼容性需要分别验证；本程序没有相应认证。
- **系统捕获提示：**使用系统捕获接口时可能出现系统捕获边框，这是正常的系统提示。
- **恢复：**停止/退出会销毁输出窗口。程序没有修改游戏窗口样式、内部配置或显示模式。显式应用的游戏自动 HDR 首选项会持久保留；需要恢复跟随全局设置时，勾选允许并重新应用、重启游戏。即使强制结束程序，也不需要手动恢复显示分辨率。

## 设置、日志和源码

便携程序在自身目录存放 `settings.json` 和错误日志 `BottomScreen.log`，请放在可写目录。默认记录31.5寸、24寸、平滑缩放；其他窗口的画面不会被保存。只有显式运行自测时才保存本程序测试画面。

源码包包含C#项目和锁定的NuGet依赖列表。安装.NET 8或更新的SDK后可构建：

```powershell
dotnet build .\BottomScreen.csproj -c Release
dotnet publish .\BottomScreen.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true
```

启动内置自测（会短暂显示本程序的测试窗口，结束后自动关闭）：

```powershell
.\BottomScreen.exe --self-test --report-dir .\self-test
```

自测只验证自身测试画面，不启动、配置或操作CS2，也不会切换真实显示器的分辨率或刷新率。全屏窗口化测试会短暂显示本程序的全屏彩色测试图，结束后自动关闭。

第三方组件的许可证见 `THIRD-PARTY-NOTICES.txt`。
